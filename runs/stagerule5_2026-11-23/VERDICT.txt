THE DECOMPOSITION, AND WHY THE SELECTION MATTERS

    h_all(0) = s_F * h_rule(0) + (1 - s_F) * h_unf(0)

  an identity, not a model: the two arms partition the 31,600
  first emissions by whether the named cell was forced.

  identity holds to 2.776e-17 across all fourteen densities

  rho 0.95 -> 0.33:
      s_F        0.963 -> 0.759   (0.79x)
      h_rule(0)  0.001150 -> 0.002084   (1.81x)
      h_unf(0)   0.518998 -> 0.570565   (1.10x)
      h_all(0)   0.020127 -> 0.138987   (6.91x)

  READ THE THREE FACTORS SEPARATELY. h_all rises 6.91x, but
  h_unf -- the error rate ON an unforced cell -- barely moves
  (1.10x, and it sits near 0.52 at every single density). The
  rise is almost entirely the unforced SHARE: 1 - s_F goes
  0.0366 -> 0.2408, a 6.57x rise, and 6.57 x 1.10 = 7.22 recovers
  nearly all of the 6.91x.

  So h_all(0) is essentially a measure of HOW OFTEN the model
  steps off the forced set, times a roughly constant ~52%
  error rate once it does. Density controls the frequency of
  leaving the support, not the competence off it.

  The forced arm contributes almost nothing to h_all: 5.5% of
  it at rho = 0.95 and 1.1% at rho = 0.33. Stages RULE2 to
  RULE4 spent four stages on that term.

IS THERE STILL A HUMP?

  above the peak (11 bins)  R = 0.5976  95% [0.5793, 0.6164]  excludes 1
  below the peak (2 bins)  R = 0.9420  95% [0.9089, 0.9762]  excludes 1

  BUT A RATIO INTERVAL IS THE WRONG INSTRUMENT AT THIS SIZE.
  h_all's numerators are in the thousands, not the tens, so the
  95% interval is under 1% wide and ANY ripple is nominally
  resolved. What matters is the size of the dip against the
  range of the curve:

      full range of h_all(0)        0.1258  (7.25x end to end)
      peak at rho = 0.40             0.1459
      value at rho = 0.33            0.1390
      drop from the peak            0.0069  = 5.5% of the range

  -> NOT A HUMP. The interior maximum is a 5.5% ripple
     among the lowest bins, on a curve that rises 7.25x end
     to end. Stage RULE4's hump was a 1.54x FALL over the
     same region; this is not that, and the nominal flank
     test above is an artefact of the larger numerator.
     E1's MISS condition is therefore NOT met: it asked for
     a peak that survives, and a sub-decile ripple is not
     one. This adjudication is recorded, not hidden -- the
     registration should have set a size floor as well as a
     significance test.

WHAT THIS SAYS, AND WHAT IT STILL DOES NOT

  Registered: E1 HIT, E2 HIT, E3 MISS, E4 HIT, E5 HIT

  THE SELECTION WAS DOING THE WORK. Once the denominator is
  every rollout instead of the ones the model chose to name,
  the hump is gone and the first-emission error rate rises
  monotonically as hints are removed, 0.0201 -> 0.1390.

  WHAT THIS DOES AND DOES NOT SAY ABOUT STAGE RULE4. RULE4's
  fall is still there -- E5 reproduces its table exactly, to
  0.000e+00 -- and it is still not censoring, because there
  is none at j = 0. What changes is what it is a fall IN.
  h_rule's denominator is the model's own choice of cell,
  s_F runs 0.963 -> 0.759, so the rollouts left in it are a
  progressively more selected subset. The unconditional
  first-emission error rate over the same rollouts RISES
  monotonically. So RULE4's fall is not a statement about
  deduction quality getting better as hints are removed.

  STATED AS A LIMIT, NOT A MECHANISM: this stage shows the
  selection EXISTS and moves in the direction that would
  produce RULE4's fall. It does not prove it causes it.
  Proving that needs a like-for-like comparison -- the same
  cells scored at two densities -- and the shards carry no
  per-cell breakdown, so it cannot be done here. The honest
  claim is the weaker one: h_rule's fall is real but is not
  interpretable as a density effect on deduction quality,
  because its denominator is not held fixed across density.
  RULE4's deck gets a correction page saying that; it does
  not get quietly rebuilt, and its hump figure stands as a
  correct picture of h_rule.

  WHY E3 MISSED, AND IT IS A FINDING. The prediction fed
  finding 124's off-support error rate (0.29 at rho = 0.95,
  pooled over every deduction index) into the j = 0 slice.
  Measured here, h_unf(0) at rho = 0.95 is 0.5190 -- 1.8x the
  pooled figure. So off-support colour accuracy at the FIRST
  emission is 48%, not the 71% finding 124 reported over
  the whole trace: the model's guessing gets BETTER as the
  trace goes on, presumably because later guesses are made
  with more of the grid filled in.

  That is the same direction as finding 126 -- the first
  deduction is the worst one -- now shown on the unforced
  arm as well as the forced arm. It also means the pooled
  off-support number must not be quoted at a fixed index,
  which is exactly the extrapolation E3 was written to test.
  Still well above chance: a blind colour guess errs at
  1 - 1/q = 0.75, and 0.52 is far below that.

  WHAT IS SOLID EITHER WAY: the unforced arm is 151x to 451x
  the forced arm. The model is near-perfect when one-step
  propagation names the colour for it (0.1% to 0.3% wrong)
  and about a coin flip when it does not (~52% wrong), and
  that gap is the single largest effect in this dataset. Not
  chance, though: a blind colour guess errs at 1 - 1/q = 0.75,
  so off the forced set the model is well above guessing and
  nowhere near the near-certainty it shows on it. It is also a
  measurement no earlier stage could make, because every
  earlier stage conditioned it away.

  WHAT THIS IS NOT:

  1. Not a density threshold. h_all(0) is a rate and is never
     converted into one.
  2. Not a statement about logical validity below rho_c. There
     an off-trace colour on an unforced cell may be a different
     valid colouring, so the four added bins bound the logical
     error rate from above rather than measuring it. The ten
     fitted bins carry the clean statement.
  3. Not clustered by instance. All 79 runs share the same 400
     instances per bin and the shards carry no per-instance
     breakdown, so no interval here can account for that, and
     the jackknife's 79 runs are not 79 exchangeable replicates.
  4. Not a reason to submit anything. No training follows from
     any outcome, as registered. The repair-and-continue rollout
     eval stays hshunt's call.
