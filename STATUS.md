16. **The train−val gap in `history.json` is not a fit diagnostic, and the encoding leaks the colouring through TOKEN ORDER** (measured 10-26; `49655447` quantifies the consequences). Two separate problems. (i) `train_nll` is `epoch_loss/epoch_n`, averaged over the epoch **while the weights update**, against a `val_nll` on end-of-epoch weights: the bias is **+0.3263 at epoch 10** on the N=96 control and decays as the curve flattens, so the *sign* of a ±0.03 gap carries no information — especially against `n_val=300`, whose own difficulty draw is worth a few hundredths. Only the N=48 20000-instance runs have an unambiguous gap (**−0.1666**). (ii) `planted_regular_graph` appends edges in class-pair block order and fills `adj[v]` in that order, so **`adj[v]` lists v's neighbours sorted by their TRUE COLOUR for 100.0% of nodes at N=24, 48 and 96**, and `encode_instance` emits `adj[i]` in raw table order. For **61–67%** of nodes the neighbours cover all q−1 other colours, so the one absent colour block identifies v's own colour. Round events are emitted in ascending node index for **100.0%** of rounds — the source of the layer-0 "sorted-order confound". **This is not memorization: it generalizes to every fresh instance from this generator, so no train/val diagnostic can detect it.** (iii) **`49655447` settled it, and it is load-bearing, not incidental** (deck `notebooks/sudoku_leak_2026-10-26`, sent). All four pre-registrations resolved: (a)(b)(c) confirmed, (d) uninformative — all three floor out, and the N=48 drop (−0.9300) exceeds N=96's (−0.9025), so there is no gradient in problem hardness. Well-formed output also collapses (N=96: 0.958→0.185), i.e. the model stops emitting a parseable trace at all. **Memorization is the smaller story and is real but bounded**: +0.0583 (N=48 @20000, p=1.2e-08), +0.0717 (N=96 ctrl @20000, p=3.4e-04), **−0.0133 at 80000 (p=0.355) — data closes it**, pre-registered and confirmed.
